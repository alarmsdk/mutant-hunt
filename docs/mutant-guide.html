Key ideas Temel kavramlar

A mutant is a copy of the correct program with one small, deliberate fault. A test kills a mutant when the mutant's output differs from the test's expected value (or the mutant throws). A mutant that no test kills survives.

Mutation score = killed mutants ÷ non-equivalent mutants. None of the seven mutants here is equivalent: each one can be killed by some test.

Mutants stand in for real mistakes. If a test suite cannot tell the correct program from a slightly wrong one, it would not catch that mistake in real code either.

Mutant, doğru programın içine bilerek tek bir küçük hata yerleştirilmiş bir kopyasıdır. Bir test, mutantın çıktısı testin beklenen değerinden farklıysa (ya da mutant exception fırlatırsa) o mutantı öldürür. Hiçbir testin öldüremediği mutant hayatta kalır.

Mutasyon skoru = öldürülen mutantlar ÷ eşdeğer olmayan mutantlar. Buradaki yedi mutantın hiçbiri eşdeğer değildir; her birini öldüren bir test vardır.

Mutantlar gerçek hataların vekilidir. Bir test takımı doğru programı hafifçe yanlış olanından ayırt edemiyorsa, aynı hatayı gerçek kodda da yakalayamaz.

The RIPR model RIPR modeli

For a test to reveal a fault, four things must happen in order:

  • Reachability – the faulty statement is executed.
  • Infection – executing it produces a wrong internal state.
  • Propagation – the wrong state reaches the output.
  • Revealability – the test's oracle (the expected value) actually checks that output, and is correct.

Every card below walks through these four steps for one mutant.

Bir testin bir hatayı ortaya çıkarması için sırasıyla dört şey olmalıdır:

  • Erişim (Reachability) – hatalı ifade çalıştırılır.
  • Bulaşma (Infection) – çalıştırılması yanlış bir iç durum üretir.
  • Yayılma (Propagation) – yanlış durum çıktıya ulaşır.
  • Görünürlük (Revealability) – testin oracle'ı (beklenen değer) bu çıktıyı gerçekten kontrol eder ve doğrudur.

Aşağıdaki her kart, bir mutant için bu dört adımı tek tek inceler.

INVALID tests: the oracle problem INVALID testler: oracle problemi

Before running the mutants, the server runs the correct implementation. If the student's expected value is wrong, the test is INVALID and earns nothing: "Your expected value is wrong – your oracle failed!"

This is the R in RIPR failing on the test side. A test with a wrong oracle cannot reveal anything, however clever its inputs. Typical cause: guessing 1-based indices, or forgetting that the first occurrence is required.

Sunucu mutantları çalıştırmadan önce doğru implementasyonu çalıştırır. Öğrencinin beklenen değeri yanlışsa test INVALID sayılır ve puan getirmez: "Your expected value is wrong – your oracle failed!"

Bu, RIPR'daki son R'nin test tarafında başarısız olmasıdır. Oracle'ı yanlış olan bir test, girdileri ne kadar zekice seçilmiş olursa olsun hiçbir şeyi ortaya çıkaramaz. Tipik neden: index'leri 1'den başlatmak ya da ilk eşleşmenin istendiğini unutmak.

The reference implementation Doğru implementasyon

/** Returns the index of the first occurrence of target in list, or -1 if target is not present. */
int indexOf(List<Integer> list, int target) {
    for (int i = 0; i < list.size(); i++) {
        if (list.get(i) == target) return i;   // target is an int → Integer is unboxed, values are compared
    }
    return -1;
}

What goes wrong Ne bozuluyor

Between two Integer objects, == asks "same object?", not "same value?". Autoboxing (Integer.valueOf) returns cached objects for −128…127, so small values happen to share one object and compare equal. For any other value there are two different objects, the match is never found, and the mutant returns -1.

The game simulates this rule explicitly ("equal and within −128…127") so the result does not depend on the JVM option -XX:AutoBoxCacheMax.

İki Integer nesnesi arasında ==, "aynı değer mi?" diye değil "aynı nesne mi?" diye sorar. Autoboxing (Integer.valueOf), −128…127 aralığı için önbellekteki nesneleri döndürür; bu yüzden küçük değerler tesadüfen aynı nesneyi paylaşır ve eşit görünür. Diğer tüm değerler için iki ayrı nesne oluşur, eşleşme hiç bulunmaz ve mutant -1 döndürür.

Oyun bu kuralı açıkça taklit eder ("eşit ve −128…127 aralığında"); böylece sonuç -XX:AutoBoxCacheMax JVM ayarına bağlı olmaz.

Coverage is not detection Kapsam, hata yakalamak değildir

The three survivors are exactly the data-dependent faults. M3 needs duplicates, M6 needs a larger element in front, M7 needs a large value. None of these is a path through the graph, so no structural criterion demands them. Structural coverage tells you which code has been executed; input space partitioning and mutation analysis tell you which situations have been tried. Round 3 works best when students derive tests from the CFG and from the input domain (occurrences: 0 / 1 / many; position: first / middle / last; order: sorted / unsorted; magnitude: small / large / negative).

Hayatta kalan üç mutant tam olarak veriye bağlı hatalardır. M3 tekrar eden değer, M6 önde daha büyük bir eleman, M7 büyük bir değer ister. Bunların hiçbiri grafikte bir yol değildir; bu yüzden hiçbir yapısal kriter onları talep etmez. Yapısal kapsam hangi kodun çalıştığını söyler; girdi uzayı bölümleme ve mutasyon analizi ise hangi durumların denendiğini söyler. Tur 3, öğrenciler testleri hem CFG'den hem de girdi uzayından türettiğinde en iyi sonucu verir (geçme sayısı: 0 / 1 / çok; konum: ilk / orta / son; sıra: sıralı / sırasız; büyüklük: küçük / büyük / negatif).

Three tests kill all seven mutants, and three is the minimum. Why not two?

  • M5 is only reachable when the target is absent, so one "not found" test is required. In a "not found" test, M1–M4 and M7 all return the correct -1.
  • M1–M4 and M7 therefore need "found" tests. A single found test cannot kill both M3 (needs a duplicate) and M1+M2 together (needs the first occurrence to be both first and last, i.e. a one-element list, which cannot contain a duplicate).

So the Round 2 limit of four tests leaves room for one mistake. Great for a debrief: "Who reached 7/7 with 3 tests?"

Üç test yedi mutantın hepsini öldürür ve üç, mümkün olan en az sayıdır. Neden iki olmaz?

  • M5'e yalnızca hedef listede yokken erişilir; bu yüzden bir "bulunamadı" testi şarttır. "Bulunamadı" testinde M1–M4 ve M7'nin hepsi doğru sonuç olan -1'i döndürür.
  • Dolayısıyla M1–M4 ve M7 için "bulundu" testleri gerekir. Tek bir "bulundu" testi hem M3'ü (tekrar gerekir) hem de M1+M2'yi birlikte öldüremez. İkisi için ilk eşleşmenin hem ilk hem son konumda olması, yani tek elemanlı bir liste gerekir; tek elemanlı listede de tekrar olamaz.

Yani Tur 2'deki dört test sınırı bir hataya yer bırakır. Tartışma için güzel bir soru: "Kim 3 testle 7/7 yaptı?"
